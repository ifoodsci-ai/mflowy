# PILOT-AI4S 系统设计稿

**全称**：**P**rior-**I**nherited **L**oop for **O**ptimization and **T**esting  
**中文名**：**先验继承闭环优化测试系统**  
**副标题**：*Agentic Clean–Model–BO–Wet-lab Closed Loop with Prior Inheritance and Learning Gate*  
**内部工程代号**：TriPIL（Tri-subsystem Prior-Inherited Loop）  
**文档状态**：草案 v1.0（已命名，基于 v0.2 三子系统 agent 会话草案整理）  
**系统边界**：Clean、Model、BO 三个子系统，均为**独立 agent 会话**；湿实验为外部环境（人工或自动化实验室）。  
**核心闭环**：`Clean → Model → BO → Wet-lab → 学习门禁 → Clean（继承先验）或继续/收敛`  
**统一范式**：每个子系统 = **继承与先验讨论建档（独立 agent 会话）→ 核心执行（POMDP 或 Optuna 驱动）→ 产出与先验更新**。

## 1. 系统总览

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                        PILOT-AI4S 闭环                                       │
│                                                                              │
│  ┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────────────────┐    │
│  │  Clean  │────▶│  Model  │────▶│   BO    │────▶│  Wet-lab（外部）     │    │
│  │ agent会话│     │ agent会话│     │ agent会话│     │ 人工/自动化实验室     │    │
│  └─────────┘     └─────────┘     └─────────┘     └──────────┬──────────┘    │
│       ▲                                                       │              │
│       │              继承先验（学习门禁触发）                    │              │
│       └───────────────────────────────────────────────────────┘              │
│         学习门禁：预测≈真实且累计量达标 → 继续/收敛                            │
│                  预测≠真实（差距过大）→ 回 Clean 继承先验                      │
└──────────────────────────────────────────────────────────────────────────────┘
```

**命名与机制对应**：

| 名称元素 | 含义 | 对应机制 |
|---|---|---|
| **P**rior-**I**nherited | 先验继承 | Clean→Model→BO 逐级只读继承先验，显式覆盖修正 |
| **L**oop | 闭环 | Clean→Model→BO→Wet-lab→门禁→Clean 的 DBTL 循环 |
| **O**ptimization | 优化 | BO 以预测模型为虚拟代理做贝叶斯优化 |
| **T**esting | 测试验证 | 湿实验验证 + 学习门禁判断预测–真实一致性 |

**三个子系统均为独立 agent 会话**，会话间通过**先验档案 + 数据产物 + 接口契约**传递状态。

## 2. 子系统一：Clean

### 2.1 业务流程

```
┌─────────────────────────────────────────────────────────────┐
│ Clean 子系统（独立 agent 会话）                                │
│                                                             │
│  步骤1：先验讨论与建档（独立 agent 会话）                       │
│         │                                                   │
│         ▼                                                   │
│  ┌──────────────────────────────────────────────────┐       │
│  │ POMDP 循环                                        │       │
│  │                                                  │       │
│  │  缺陷检测算子 ──▶ agent 拿到「检测到的数据缺陷」     │       │
│  │       ▲               +「清洗算子空间」            │       │
│  │       │                    │                     │       │
│  │       │                    ▼                     │       │
│  │       │              agent 决策：选择清洗算子       │       │
│  │       │                    │                     │       │
│  │       │                    ▼                     │       │
│  │       │              执行清洗算子                  │       │
│  │       │                    │                     │       │
│  │       └────────────────────┘                     │       │
│  │         （再次缺陷检测，直到缺陷收敛/预算耗尽）        │       │
│  └──────────────────────────────────────────────────┘       │
│         │                                                   │
│         ▼                                                   │
│  产出：干净数据集 + 质量元数据 + Clean-Prior 快照              │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 步骤 1：先验讨论与建档（独立 agent 会话）

**会话参与方**：Clean agent、湿实验数据负责人、领域专家（可异步）。

**建档内容**（`clean_prior_v{n}.yaml`）：

| 档案块 | 条目示例 |
|---|---|
| 数据来源先验 | assay 类型、单位、检测限、重复次数、批次划分 |
| 缺陷类型先验 | 已知噪声模式、异常标签、缺失值、批次效应、失败实验判定 |
| 清洗算子空间先验 | 可用算子清单（去重、标准化、标签修正、异常剔除、失败标记、切分）及适用条件 |
| 标签语义先验 | 活性/亲和力定义、低值语义 |
| 序列空间先验 | 突变表示规范、野生型参考 |
| 切分先验 | 按位点/批次/同源簇切分，防泄漏 |
| 停止准则先验 | 缺陷收敛判据、POMDP 预算上限 |

### 2.3 步骤 2：POMDP 清洗循环

**POMDP 五元组映射**：

| 要素 | 在本子系统中的含义 |
|---|---|
| **状态 S** | 数据集的真实质量状态（缺陷集合、噪声水平、批次偏差） |
| **观测 O** | 缺陷检测算子输出的缺陷报告（部分可观测） |
| **动作 A** | 清洗算子空间中的算子选择与参数（去重、标准化、标签修正、剔除、标记、切分等） |
| **转移 T** | 执行清洗算子后数据质量状态的变化 |
| **奖励 R** | 缺陷减少量 / 下游可用性提升 / 清洗代价惩罚 |

**循环流程**：

1. **缺陷检测算子**运行，输出当前数据集的缺陷报告（如：重复率、标签噪声估计、批次偏差、缺失率、泄漏风险）。
2. **agent 决策**：拿到「缺陷报告 + 清洗算子空间 + 先验约束」，选择下一清洗算子及参数。
3. **执行清洗算子**：作用于数据集，记录操作日志。
4. **回到缺陷检测算子**：重新检测，判断缺陷是否收敛或达到停止准则。
5. 循环直至收敛或预算耗尽。

**关键设计点**：
- 缺陷检测算子与清洗算子均**版本化注册**，agent 只能从注册空间选择。
- 每步操作写入 `clean_action_log`，保证可追溯。
- POMDP 的奖励函数由先验中的“质量阈值”与“下游可用性”共同定义。

### 2.4 步骤 3：产出与先验更新

- **产出**：干净数据集（统一 schema）+ 质量元数据 + 切分方案 + `clean_action_log`
- **先验更新**：将本轮实际缺陷模式、有效/无效算子、检测阈值偏差写回 `clean_prior_v{n+1}`
- **接口**：`variant_id, sequence, mutations, assay_condition, label, label_confidence, batch_id, split, failure_flag, metadata`

## 3. 子系统二：Model

### 3.1 业务流程

```
┌──────────────────────────────────────────────────────────────────┐
│ Model 子系统（独立 agent 会话）                                     │
│                                                                  │
│  步骤1：继承与先验讨论建档（独立 agent 会话）                         │
│         │ 继承 Clean-Prior 快照                                    │
│         ▼                                                        │
│  步骤2：主 agent 决策层                                            │
│         ├─ 从先验拿到：前沿研究模型候选、基线选择、CV 方案             │
│         ├─ 钉死 CV 方案                                           │
│         └─ 逐模型分发 HPO 任务                                     │
│                │                                                 │
│                ▼                                                 │
│  ┌───────────────────────────────────────────────────────┐       │
│  │ 每个模型一个独立 HPO agent（嵌套 POMDP）                  │       │
│  │                                                       │       │
│  │  agent 拿到 HPO 产物 ──▶ 动作空间（调参 / 调参数空间 / FE）│       │
│  │         ▲                        │                    │       │
│  │         │                        ▼                    │       │
│  │         └──────────── 发起 HPO 任务 ◀──────────────┘    │       │
│  │         （循环直至 HPO 预算耗尽/收敛）                     │       │
│  └───────────────────────────────────────────────────────┘       │
│                │                                                 │
│                ▼                                                 │
│  步骤3：主 agent 汇总所有模型 CV 结果 → 决策最佳模型                  │
│         │                                                        │
│         ▼                                                        │
│  步骤4：用最佳模型的 HPO 参数做终训 → 评估 → 解释                    │
│         │                                                        │
│         ▼                                                        │
│  产出：最佳模型 + 预测接口 + Model-Prior 快照                       │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 步骤 1：继承与先验讨论建档（独立 agent 会话）

**会话参与方**：Model agent、Clean agent（继承交接）、建模负责人、湿实验代表。

**继承动作**：挂载 `inherited_from: clean_prior_v{n}` 只读快照，逐条确认（acknowledged / overridden / deprecated）。

**新增/覆盖内容**（`model_prior_v{n}.yaml`）：

| 档案块 | 条目示例 | 与上游关系 |
|---|---|---|
| 数据可信度先验 | 低置信批次降权策略 | 继承 Clean 质量元数据 |
| 前沿模型候选 | 从文献/预训练资产中整理的模型清单（PLM、GP、集成、树模型等） | 新增 |
| 基线选择先验 | 零样本 PLM、随机、简单回归等基线 | 新增 |
| CV 方案先验 | 切分策略、指标、重复次数、防泄漏约束 | 继承 Clean 切分先验 |
| HPO 动作空间先验 | 调参、调参数空间、特征工程（FE）的允许范围 | 新增 |
| 不确定性先验 | 校准要求、OOD 判定 | 新增 |
| 模型决策先验 | 最佳模型选择准则（CV 均值+方差+校准） | 新增 |

### 3.3 步骤 2：主 agent 决策层

1. **从先验拿到**：前沿研究中的模型候选列表、基线选择、CV 方案。
2. **钉死 CV 方案**：切分、指标、重复次数一经确定即冻结，所有模型共用，保证可比性。
3. **逐模型分发 HPO 任务**：每个模型派生一个独立 HPO agent 会话。

### 3.4 步骤 3：嵌套 POMDP——每个模型的 HPO agent

**每个独立 agent 监控一个模型 HPO**，POMDP 映射：

| 要素 | 含义 |
|---|---|
| **状态 S** | 该模型的真实最优超参/特征配置 |
| **观测 O** | HPO 产物（当前 trial 的指标、学习曲线、参数重要性） |
| **动作 A** | 调参 / 调参数空间 / 特征工程（FE） |
| **转移 T** | 发起 HPO 任务后模型性能分布的变化 |
| **奖励 R** | CV 指标提升 / 预算效率 / 稳定性 |

**循环流程**：

1. agent 拿到 **HPO 产物**（历史 trial 结果、当前最佳配置、参数敏感度）。
2. agent 在**动作空间**（调参、调整参数空间、特征工程）中选择下一动作。
3. **发起 HPO 任务**（如 Optuna trial 或新一轮搜索）。
4. 回到步骤 1，直至 HPO 预算耗尽或收敛。
5. 输出该模型的 HPO 最优配置与 CV 结果。

**关键设计点**：
- 每个 HPO agent 独立会话、独立预算，互不干扰。
- 动作空间由 Model-Prior 约束，防止越界搜索。
- HPO 产物结构化记录，供主 agent 汇总。

### 3.5 步骤 4：主 agent 汇总决策与终训

1. **汇总所有模型的 CV 结果**（均值、方差、校准、训练成本）。
2. **决策最佳模型**：按先验中的选择准则（如 CV 均值优先、方差惩罚、校准达标）。
3. **用最佳模型的 HPO 参数进行终训**：在完整训练集上训练。
4. **评估**：留出集/时间外验证、校准检查、OOD 检测。
5. **解释**：特征重要性、突变效应归因、不确定性来源。
6. **产出**：`predict(candidates) -> mean, uncertainty, ood_flag, model_version`

### 3.6 步骤 5：先验更新

将实际 CV 排名、HPO 有效动作、校准漂移、模型失效区域写回 `model_prior_v{n+1}`，供 BO 继承。

### 4.2 步骤 1：继承与先验讨论建档（独立 agent 会话）

**会话参与方**：BO agent、Model agent（继承交接）、优化负责人、湿实验通量负责人。

**继承动作**：挂载 `inherited_from: [clean_prior_v{n}, model_prior_v{n}]`，逐条确认。

**新增/覆盖内容**（`bo_prior_v{n}.yaml`）：

| 档案块 | 条目示例 | 与上游关系 |
|---|---|---|
| 搜索空间先验 | 可合成/可表达候选域、禁止突变、长度约束 | 继承 Clean 序列规范 |
| 预测可信域先验 | 模型可信区域、OOD 惩罚规则 | 继承 Model 不确定性先验 |
| 采集策略先验 | Optuna sampler（TPE/GP）、EI/UCB、探索–利用偏好 | 新增 |
| 批量与通量先验 | 每轮推荐数量、湿实验构建周期 | 新增 |
| 安全/多目标先验 | 活性–稳定性权衡、毒性/表达约束 | 继承 Clean 标签语义 |
| 停止准则先验 | 预算上限、收敛判据、regret 阈值 | 新增 |

### 4.3 步骤 2：基于 Optuna 执行 BO

- **Optuna 作为优化引擎**，目标函数为**预测模型作为虚拟试验代理**（不调用真实湿实验）。
- **采集函数**由先验配置（TPE / GP-based / EI / UCB / Thompson）。
- **批量推荐**：按湿实验通量输出一批候选。
- **约束处理**：OOD 惩罚、可合成性过滤、安全约束。
- **记录**：每个 trial 的推荐理由、采集分数、预期信息增益。

### 4.4 步骤 3：输出带预测的 CSV 推荐

**CSV schema**：

```
variant_id, sequence, mutations,
prediction_mean, uncertainty, ood_flag,
acquisition_score, expected_information_gain,
rationale, constraint_status, model_version, bo_prior_version
```

### 4.5 步骤 4：先验更新

将本轮推荐命中/落空、约束违反、采集策略有效性写回 `bo_prior_v{n+1}`。

## 5. 完整 AI4S 闭环与学习门禁

### 5.1 闭环流程

```
Clean ──▶ Model ──▶ BO ──▶ 推荐 CSV ──▶ Wet-lab（人工/自动化实验室）
  ▲                                              │
  │                                              ▼
  │                                     更新结果 CSV
  │                                              │
  │                              ┌───────────────┴───────────────┐
  │                              │        学习门禁判断             │
  │                              │                               │
  │                    ┌─────────┴─────────┐                     │
  │                    │                   │                     │
  │                    ▼                   ▼                     │
  │         预测≈真实 且 累计量达标    预测≠真实（差距过大）         │
  │                    │                   │                     │
  │                    ▼                   ▼                     │
  │            继续 BO 推荐 / 收敛      继承先验 → 回到 Clean       │
  │            （进入下一轮）            （重新清洗/建模/优化）       │
  └──────────────────────────────────────────────────────────────┘
```

### 5.2 Wet-lab 外部实验

- **执行方**：人工或自动化实验室（anyway）。
- **输入**：BO 输出的推荐 CSV（含预测值）。
- **输出**：更新后的结果 CSV（真实标签 + 实验条件 + 失败原因 + 批次 ID）。
- **要求**：结果 CSV 必须包含 `variant_id, sequence, true_label, assay_condition, batch_id, failure_flag`，保证可回流。

### 5.3 学习门禁（Learning Gate）

学习门禁是 PILOT-AI4S 的**闭环切换器**，决定下一轮走向。判断依据两类信号：

| 信号 | 判断 | 动作 |
|---|---|---|
| **预测接近真实** 且 **累计实验量达到学习门禁阈值** | 模型与优化器工作正常，数据量足够 | 进入下一轮 BO 推荐；或满足收敛准则则终止 |
| **真实结果与预测差距过大** | 模型失准 / 分布漂移 / 数据缺陷 / 候选空间越界 | **继承先验，回到 Clean**，重新走 Clean→Model→BO |

**门禁参数**（建议由先验配置）：

- **预测–真实一致性阈值**：如 Spearman 相关性下限、校准误差上限、MAE 容忍度。
- **累计量阈值**：累计湿实验样本数 / 累计轮次。
- **差距过大判定**：连续 N 个样本超出置信区间，或批次级系统性偏差。
- **门禁触发后的继承动作**：Clean 继承上一轮 Clean-Prior + Model-Prior + BO-Prior 的失败信号条目，进入新一轮先验讨论。

### 5.4 闭环先验继承

门禁触发回 Clean 时，**继承先验**：

1. **Clean** 继承 `clean_prior_v{n}` + `model_prior_v{n}` 中的“模型失准区域” + `bo_prior_v{n}` 中的“推荐落空记录”，增补失败模式条目。
2. **Model** 重新继承更新后的 Clean-Prior，增补“预测–真实偏差诊断”。
3. **BO** 重新继承更新后的 Clean-Prior + Model-Prior，增补“采集策略失效分析”。
4. 进入下一轮 DBTL。

## 6. 子系统间接口契约

| 接口 | 上游→下游 | 必须保证 |
|---|---|---|
| Clean→Model | 干净数据集 + `clean_prior_v{n}` | 标签置信度、批次信息、无泄漏切分、失败标记、算子日志 |
| Model→BO | 最佳模型 + 预测接口 + `model_prior_v{n}` | 校准后不确定性、OOD 标记、模型版本、HPO 配置 |
| BO→Wet-lab | 推荐 CSV | 可合成、可表达、通量匹配、约束满足、推荐理由、预测值 |
| Wet-lab→Clean | 结果 CSV + 门禁信号 | 真实标签、实验条件、失败原因、批次 ID、预测–真实对照 |

## 7. Agent 会话拓扑

```
Clean agent 会话
  └─ 先验建档会话
  └─ POMDP 清洗循环（缺陷检测 ↔ 算子决策 ↔ 执行）

Model agent 会话
  └─ 继承与先验建档会话（继承 Clean）
  └─ 主 agent：CV 钉死 + 模型分发 + 汇总决策 + 终训评估解释
       └─ HPO agent × N（每模型一个独立会话，嵌套 POMDP）

BO agent 会话
  └─ 继承与先验建档会话（继承 Clean + Model）
  └─ Optuna BO 执行（预测模型为虚拟代理）
  └─ 推荐 CSV 输出

Wet-lab（外部）
  └─ 执行推荐 → 结果 CSV → 学习门禁判断 → 回 Clean 或继续
```

## 8. 先验继承机制（系统级设计）

### 8.1 继承链

```
Clean-Prior ──只读快照──▶ Model-Prior ──只读快照──▶ BO-Prior
     │                       │                       │
     └──── 先验更新 ◀────────┴──── 先验更新 ◀────────┘
                 （学习门禁触发回流）
```

### 8.2 继承规则

1. **只读继承**：下游先验档案挂载上游先验快照，不得静默篡改。
2. **显式覆盖**：下游若需修正上游条目，必须写入 `overrides`，注明目标条目、新陈述、原因与负责人。
3. **逐条确认**：下游建档时对继承条目逐条标记 `acknowledged / overridden / deprecated`，未确认条目不得进入核心处理。
4. **版本化**：每次先验讨论产生新版本 `v{n+1}`，保留历史快照。
5. **可追溯**：每条先验含 `source / confidence / owner / applies_to`。

### 8.3 统一先验档案 Schema（建议）

```yaml
prior_id: model_prior_v3
subsystem: model            # clean | model | bo
inherited_from:
  - clean_prior_v3          # 只读快照引用
entries:
  - id: M-001
    statement: "GP 在突变位点数 <5 时校准良好"
    source: "model_prior_v2 实测"
    confidence: high        # high | medium | low
    owner: modeling_lead
    applies_to: [uncertainty_calibration]
  - id: M-002
    statement: "批次 B07 标签置信度低，训练时降权"
    source: "inherited: clean_prior_v3/C-012"
    confidence: medium
    owner: wetlab_lead
overrides:
  - target: "clean_prior_v3/C-009"
    new_statement: "切分改为按同源簇"
    reason: "发现跨簇泄漏"
    owner: modeling_lead
```

## 9. 评估指标

| 层级 | 指标 |
|---|---|
| Clean | 缺陷检出率、清洗后质量提升、算子有效性、泄漏率 |
| Model | CV 排序相关性、校准误差（ECE）、OOD 检测能力、HPO 预算效率 |
| BO | 推荐命中率、累计 regret、约束违反率、预期信息增益实现度 |
| 闭环 | 预测–真实一致性、达到目标所需湿实验量、门禁触发次数与原因分布、性能提升倍数 |

## 10. 非功能需求

1. **可追溯**：每个推荐批次可追溯到模型版本、先验版本、数据切分版本与 BO 配置。
2. **可复现**：先验档案、数据集、模型、BO 配置、门禁参数均版本化。
3. **可审计**：先验条目的继承、覆盖、废弃，以及 Clean 算子操作日志均留痕。
4. **可扩展**：支持新增 assay、多目标、批量约束、安全约束与新的缺陷检测/清洗算子。
5. **失败可处理**：湿实验失败数据不丢弃，作为负信息回流并标记原因。
6. **会话隔离**：三个子系统与每个 HPO agent 均为独立会话，预算与状态互不污染。

## 11. 风险与开放问题

| 风险/问题 | 说明 | 建议 |
|---|---|---|
| POMDP 缺陷检测不完备 | 检测算子漏检导致清洗不彻底 | 缺陷算子版本化 + 多算子集成 |
| HPO agent 预算失控 | 每模型独立 HPO 可能耗尽资源 | 先验设定每模型预算上限与总预算 |
| CV 方案钉死后不适配 | 数据分布变化导致 CV 失真 | 学习门禁触发回 Clean 时允许重新讨论 CV |
| 预测–真实差距归因难 | 门禁触发后不知是数据/模型/优化问题 | 继承先验时强制做三方归因诊断 |
| 累计量门禁阈值主观 | 阈值设定影响收敛速度 | 先验配置 + 每轮复盘调整 |
| 推荐 CSV 不可合成 | BO 越界推荐 | BO-Prior 约束 + Wet-lab 预筛反馈 |
| 先验条目膨胀 | 每轮增补导致档案臃肿 | 定期归档低置信/失效条目，保留历史快照 |

---

## 12. 一句话总结

**PILOT-AI4S（先验继承闭环优化测试系统）** 由 **Clean（POMDP 缺陷检测–清洗算子循环）、Model（主 agent + 每模型 HPO agent 嵌套 POMDP）、BO（Optuna + 预测模型虚拟代理）** 三个独立 agent 会话子系统构成；每个子系统以“继承与先验讨论建档”为第一步；湿实验作为外部环境更新结果 CSV，由**学习门禁**判断：预测≈真实且累计量达标则继续/收敛，差距过大则继承先验回到 Clean，形成可追溯、可复现、随闭环增厚的 AI4S 设计–构建–测试–学习循环。
