# SOLVE — 做题（判据见骨架）

## 方法选择（决策权序：用户指定 > π 按题型自选）

用户指定则从其指定（点名某管线/算法/现有脚本，从之）；未指定按题型自行判断——建模/清洗/NLP/CV/代码/优化类各选其法。判断依据 = SPEC 记录的评审方式与 deliverables 形态：有分赛围绕指标做，人工评审赛围绕可复现工作流做。所选方法若自带 skill/文档，以其为主——本回路只见**输入输出契约**：外环给冻结数据快照 + SPEC 产物，solve 回交付物 + 验证报告；内环不必须是 MDP，是任意满足下述硬要求的求解过程。

## 两条硬要求（方法中立，不可豁免）

1. **可复现**：解题过程落成 run_all 类一键脚本或 notebook，零手工步骤
2. **可验证**：自带或现建一个本地验证门，提交前全绿

## 诚实性纪律

题目文档声称但数据中不存在的缺陷，如实记 verified-clean，**不制造修复**；指标不好看也照实呈现并解释。

## 陷阱

- 内环步级状态对外环不可见——外环只判两件事：验证门绿不绿、交付物能不能一键再生；别在外环重复内环的中间观测
